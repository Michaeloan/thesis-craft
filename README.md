# 论文守意 · Thesis Craft

**审查论文论述，润色中文正文；在长文的章节、口径和多轮修改中保留论证关系。**

论文守意是一个可安装的 Agent Skill，配套 Python 标准库脚本管理来源快照、章节索引、上下文和修改记录。模型负责理解、审查和写作；本地脚本不调用模型 API，也不自动判断论文事实真假。

## 为什么做这个 Skill

论文写到后期，我常常知道自己想表达什么，却很难一次把想法写成准确、自然、逻辑清楚的学术文字：词不达意，句子读起来不顺，比较和判断散在段落各处。交给通用模型后，又可能被压得过短、补进空泛解释，或把本来确定的研究口径改掉。为了把文字改回想要的方向，往往要反复指出同一问题、补回已经给过的上下文，再重做审查和修改。

长论文还会放大这个负担。切换章节或会话后，前文定义、已确认的修改和未解决问题容易丢失，作者不得不重复说明；模型也可能每轮从头理解，反复生成相似内容。这些往返会消耗时间、上下文和 token，却不一定让论文更好。

创作这个 Skill，是想把“审查哪里、为什么改、改后保留什么”说清楚，并在长文项目中带着必要的原文与作者决定继续工作，减少无效重复。它的目标是让修改更贴近作者本意，少走返工轮次；目前没有可靠量化实际节省了多少 token，因此不把节省幅度作为已验证的效果宣传。

## 两个核心能力

| 审查 | 润色 |
|---|---|
| 指出原文哪里有问题、依据是什么、影响什么，并给出可执行建议 | 根据段落任务修句或组织已有论述，保留作者实际要表达的结果和判断 |
| 区分确定问题、待核实事项和可选改善 | 让比较、依据和推论关系更清楚，而非按比例压缩或逐句换词 |
| 审查意见不能自动变成作者决定 | 改完检查有没有损失原意，也检查正文是否真的变清楚 |

长文模式可导入 DOCX、Markdown 和 UTF-8 文本，读取相关定义、图表说明与相邻段落，保存作者决定、候选稿、未决事项并在新会话续接。短片段不需要建项目。相近论文检索、图表和 Word 处理按需调用。

**修改前**

> 这些任务需要一条从逐栋屋顶资源、适装面积、装机和发电潜力，到碳减排、经济效益、负荷匹配和部署路径的连续证据链。本研究据此开展广州全域逐栋评估，并以建筑功能和屋顶形态作为贯穿资源识别、潜力测算和部署分析的共同接口。

> 上述任务要求将逐栋屋顶资源识别、适装面积估算、装机与发电潜力测算，与碳减排、经济效益、负荷匹配及部署路径分析相衔接。基于此，本研究开展广州全域逐栋评估，并以建筑功能和屋顶形态作为贯穿资源识别、潜力测算与部署分析的统一分类依据。

**本例的变化**：把“连续证据链”“共同接口”换成可以沿原文核对的分析环节，并说明功能与形态怎样贯穿分析。这是一次实际模型输出，不是作者认可稿，也不能单独证明 Skill 整体优于普通提示。该论文摘录仅在本 README 展示，不随 MIT 许可授权。

另有一个**合成示范**展示比较关系的保留：

- 原文：甲组占样本的30%，贡献48%的产出；乙组占样本的50%，贡献35%的产出。
- 候选：甲组占样本的30%，贡献48%的产出，其产出贡献高于样本占比；乙组占样本的50%，贡献35%的产出。

## 安装

下载并解压 [thesis-craft-0.5.0.zip](https://github.com/Michaeloan/thesis-craft/raw/refs/heads/main/dist/thesis-craft-0.5.0.zip)，在解压后的目录运行：

```powershell
$skillHome = Join-Path $HOME ".codex\skills"
New-Item -ItemType Directory -Force -Path $skillHome | Out-Null
Copy-Item -LiteralPath ".\thesis-craft" -Destination $skillHome -Recurse
```

如果使用自定义 `CODEX_HOME`，请将目录放入对应的 `skills` 路径。其他兼容智能体可以直接读取 `skills/thesis-craft/SKILL.md`。安装时复制整个 `thesis-craft` 文件夹。

项目源码包：[thesis-craft-0.5.0-source.zip](https://github.com/Michaeloan/thesis-craft/raw/refs/heads/main/dist/thesis-craft-0.5.0-source.zip)。

## 快速开始

只审查：

> 使用 $thesis-craft 审查这一段，说明有原文依据的问题、具体位置和建议；不要直接改写。

只润色：

> 使用 $thesis-craft 润色这一段，保留作者的论点、术语、比较及数据关系，返回一版可直接使用的正文。

审查并润色：

> 使用 $thesis-craft 检查并润色这部分。依据现有数据和上下文解决表达或论述问题；没有依据的实质判断请标为待核实，不要编造。

长文项目：

> 使用 $thesis-craft 在副本上处理这篇论文。先只读导入并建立章节索引，再按小节读取原文与相关材料。保存候选稿、检查记录及未决事项；作者未接受的修改不要标成已接受。

当用户明确要求补论述或调整章节时，Skill 会读取相应规则并查找现有依据。它不会把普通语言润色自动扩展为全文重写或联网研究。

## 长论文辅助工具

需要 Python 3.10 或更新版本；脚本仅使用标准库。

```powershell
python -B skills/thesis-craft/scripts/project.py --project local/my-thesis init
python -B skills/thesis-craft/scripts/project.py --project local/my-thesis import PATH_TO_YOUR_COPY.md
python -B skills/thesis-craft/scripts/project.py --project local/my-thesis status
```

获取 unit ID 后，可组装当前上下文、记录候选稿及检查结果、续接或导出：

```text
project.py --project PATH context --unit ID --task "审查并润色"
project.py --project PATH record --context CONTEXT_ID --candidate TEXT_FILE --review REVIEW.json
project.py --project PATH resume
project.py --project PATH export --output NEW_DIRECTORY
```

上下文按关联和字符预算组装；超出预算时拆小任务，不截断当前正文。重新导入新稿后，受影响的旧记录需要复核。脚本不改原文件，不提供保真 DOCX 回写。

## 验证结果与限制

本地运行的 v0.5 版 56 项脚本回归测试和 Skill 格式检查通过。测试验证文件导入、状态记录、失效保护与打包边界，不评价模型润色效果。为保护测试中使用的原始材料，本次公开源码包不含完整评测集、测试输入和原始生成记录。

一次实测对照使用第九轮稿中 8 组、13 段明显存在表达问题的文字：普通提示与 v0.5 各运行一次，共 16 次模型生成。对照出现局部改善，也发现反复限定没有解决、术语含义变化和审查说明与实际改动不符。因此当前**没有证据证明 v0.5 整体优于普通提示**。该测试是已用于规则调整的问题样本，不是独立留出集；复核非盲，作者接受度未测。详情见 [公开测试摘要](docs/R09_VALIDATION_PUBLIC.md)。

功能说明描述的是 Skill 如何工作，不是效果领先的承诺。公开版仅提供汇总验证说明，不公开含论文原文的整套对照材料。

## 项目结构与边界

- `skills/thesis-craft/`：安装用 Skill、专项规则、标准库脚本。
- `tools/`：构建安装包和公开源码包的工具。
- `docs/`：公开的来源说明与验证摘要。

Skill 本身不提供文献数据库、在线审稿服务、绘图模型或 Word 无损回写。文献、图表和 DOCX 任务按需使用宿主已有工具与专项说明。公开仓库不含本地原始评测集、个人运行记录或论文全文。
