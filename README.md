# 论文守意 · Thesis Craft

**用于中文毕业论文审查与润色的 Agent Skill，帮助长篇修改延续作者的研究口径、论述关系和章节上下文。**

论文写到后期，作者往往知道自己想表达什么，却难以一次写得准确、自然、清楚。通用模型有时会压缩过度、混淆论述与解释，或让不同章节承担相同任务。反复补充上下文、改回原意和重做润色，也会消耗大量时间与 token。

创作论文守意，是希望把审查意见、修改目标和论文上下文连在一起，让每一轮修改都能沿着作者原有的意思继续推进。

## 两大模块

| 发现问题 | 解决问题 |
|---|---|
| 从表达、语义关系、论证、章节推进、证据、计算和文档呈现七个层次定位问题 | 按根因选择修句、重组、补强、迁移、删除、核验或版面修复 |
| 先检查当前版本，识别过期或错误的审查意见 | 保留作者的比较、依据、推论、限定、术语和数据归属 |
| 区分表面症状与根因，并给出改后应达到的状态 | 修改后检查定义、图表、引用、摘要、结论及后文承接 |

## 长论文特色

- **章节推进检查**：核对重要地区、类型、指标和案例是否按“定义与方法—结果—讨论—结论”逐步出现，避免后文突然引入重点对象。
- **版本演化审查**：将历史问题标为已解决、部分解决、仍存在、复发、已变化或当前版本不成立，不把旧意见直接套到新稿。
- **审稿意见核实**：先回到当前正文、计算资料和来源确认意见是否成立，再决定修改；不按意见语气或数量改稿。
- **修改影响追踪**：公式、数字、术语、段落或图表变化后，自动提醒复核相关定义、引用、摘要、结论和交叉引用。
- **安全迁移与删除**：整块删除前先识别独有论据、引文和未完成事项；语义结构不使用跨段正则批量处理。
- **作者风格延续**：记录已认可案例、持续偏好、章节要求和当前任务限制，换会话后仍能继续。

短片段可直接使用，不必建立项目。长论文可导入 DOCX、Markdown 或 UTF-8 文本，按章节整理原文、相关定义、图表和作者决定，并生成候选稿与续接记录。

## Luna 实际润色案例

以下案例取自论文历史稿，由 `gpt-6-luna` 使用 Thesis Craft 完成审查和润色，展示从发现问题到解决问题的不同动作。

**发现的问题**

“连续证据链”和“共同接口”较为抽象，读者不易直接看出评估内容，以及建筑功能和屋顶形态在各环节中的具体作用。

**修改前**

> 广州电力规划已把分布式光伏置于源网荷储协同发展的框架中[4,26—27,33]。《广州市面向2035年电力供应保障规划》同时部署分布式光伏开发消纳、灵活智能配电网、多元储能和需求侧响应[33]。这些任务需要一条从逐栋屋顶资源、适装面积、装机和发电潜力，到碳减排、经济效益、负荷匹配和部署路径的连续证据链。本研究据此开展广州全域逐栋评估，并以建筑功能和屋顶形态作为贯穿资源识别、潜力测算和部署分析的共同接口。

**Luna 润色稿**

> 广州电力规划已将分布式光伏纳入源网荷储协同发展的框架[4,26—27,33]。《广州市面向2035年电力供应保障规划》进一步部署了分布式光伏开发消纳、灵活智能配电网、多元储能和需求侧响应[33]。围绕这些任务，本研究对广州全域开展逐栋评估，依次测算屋顶资源、适装面积、装机和发电潜力，并分析碳减排、经济效益、负荷匹配及部署路径。建筑功能和屋顶形态用于资源识别、潜力测算与部署分析，作为各环节共用的分类依据。

**解决方式**：将“连续证据链”展开为实际评估内容，把研究任务与规划要求连接起来；将“共同接口”改为“各环节共用的分类依据”，直接说明两个分类变量如何参与分析。原有规划依据、研究范围、引文和分析内容均予保留。

### 案例二：把容量比例说清楚

**发现的问题**：“相当于技术潜力容量的约9.1%”没有直接说明现状装机与技术潜力之间的比较关系，“释放空间”也较抽象。

**修改前**

> 截至2025年2月底，广州分布式光伏装机约3.01 GWp[168]，相当于技术潜力容量的约9.1%。现状装机与技术资源之间仍有较大释放空间，其形成原因可能涉及建筑条件、业主决策、融资、行政程序与配网承载力等多个方面[101,167,169]。不同类型屋顶的资源规模、适装能力、经济性和负荷特征可以缩小项目筛选范围，主导约束则需在单栋建筑、园区或台区尺度识别。

**Luna 润色稿**

> 截至2025年2月底，广州分布式光伏装机约3.01 GWp[168]，约为技术潜力容量的9.1%，说明现状装机与技术潜力之间仍有较大差距。造成这一差距的原因可能涉及建筑条件、业主决策、融资、行政程序和配网承载力等多个方面[101,167,169]。比较不同类型屋顶的资源规模、适装能力、经济性和负荷特征，有助于缩小项目筛选范围；主导约束则需在单栋建筑、园区或台区尺度识别。

**解决方式**：把比例的比较对象直接写出，并以“差距”承接后句，同时保留原因的可能性限定、引用和尺度判断。

### 案例三：拆清虚拟电厂的运行条件

**发现的问题**：原段已经包含虚拟电厂的功能、运行环节、本地背景和制度边界；需要改善长句节奏，区分“运行包括哪些环节”和“具备调度能力需要什么条件”。

**修改前**

> 虚拟电厂的核心作用是把分散光伏、负荷和储能聚合为可观测、可预测和可协调的资源组合，并通过相应控制与市场接口参与调度或交易[104—105,192—194]。近期综述表明，VPP运行至少包含数据采集与通信、预测和决策、异质资源协调、市场交互以及隐私和风险管理等环节[104—105]；因此，资源“被聚合”并不意味着已经具备可调度能力，计量质量、通信时延、设备控制权限和合同责任仍是必要前提。广州已发布虚拟电厂实施方案并开展相关应用[195—196]，为分散屋顶资源的协同运行提供了本地制度与案例基础。虚拟电厂并不替代屋顶权利确认和单体接网，而是在资源完成计量、通信、控制和合同接入后，提高整体可观测性和调节能力；国外市场模型只支持功能定义，不能直接证明广州的准入规则或项目收益[193—194]。

**Luna 润色稿**

> 虚拟电厂的核心作用，是将分散的光伏、负荷和储能聚合为可观测、可预测、可协调的资源组合，并通过相应的控制与市场接口参与调度或交易[104—105,192—194]。近期综述指出，VPP运行至少包括数据采集与通信、预测和决策、异质资源协调、市场交互，以及隐私和风险管理等环节[104—105]。因此，完成资源聚合并不代表资源已具备可调度能力；计量质量、通信时延、设备控制权限和合同责任仍是必要前提。广州已发布虚拟电厂实施方案，并开展相关应用[195—196]，为分散屋顶资源的协同运行提供了本地制度和案例基础。虚拟电厂不能替代屋顶权利确认和单体接网。只有在资源完成计量、通信、控制和合同接入后，虚拟电厂才能提高整体可观测性和调节能力。国外市场模型可用于说明虚拟电厂的功能定义，但不能直接证明广州的准入规则或项目收益[193—194]。

**解决方式**：拆开承担多个条件的长句，把运行机制、调度前提、本地应用和国外模型的适用范围依次讲清，保留证据边界。

## 安装

下载并解压 [thesis-craft-0.6.2.zip](https://github.com/Michaeloan/thesis-craft/raw/refs/heads/main/dist/thesis-craft-0.6.2.zip)，将其中的 `thesis-craft` 文件夹复制到 Codex 的 Skills 目录：

```powershell
$skillHome = Join-Path $HOME ".codex\skills"
New-Item -ItemType Directory -Force -Path $skillHome | Out-Null
Copy-Item -LiteralPath ".\thesis-craft" -Destination $skillHome -Recurse
```

如果使用自定义 `CODEX_HOME`，请将文件夹放入相应的 `skills` 路径。兼容的智能体也可以直接读取 `skills/thesis-craft/SKILL.md`。

源码包：[thesis-craft-0.6.2-source.zip](https://github.com/Michaeloan/thesis-craft/raw/refs/heads/main/dist/thesis-craft-0.6.2-source.zip)。

## 使用示例

只审查：

> 使用 $thesis-craft 审查这一段，指出具体位置、原文依据和修改建议；先不要改写。

只润色：

> 使用 $thesis-craft 润色这一段，保留作者的论点、术语、比较及数据关系，返回一版可直接使用的正文。

审查并润色：

> 使用 $thesis-craft 检查并润色这部分。依据现有数据和上下文处理表达与论述问题；需要补充依据的地方单独指出。

核实审查意见：

> 使用 $thesis-craft 核实这些审查意见。先检查当前稿和已有依据，区分成立、部分成立和当前版本不成立，再修改确实存在的问题。

版本回顾：

> 使用 $thesis-craft 对照旧稿和当前稿，说明历史问题哪些已解决、哪些仍存在或复发，并把剩余问题转成可执行修改。

长篇论文：

> 使用 $thesis-craft 处理这篇论文。先整理章节结构和研究口径，再按小节读取原文与相关材料。保存候选稿、作者决定和待处理事项，方便后续继续。

## 长论文辅助工具

辅助脚本使用 Python 3.10 或更新版本，仅依赖标准库：

```powershell
python -B skills/thesis-craft/scripts/project.py --project local/my-thesis init
python -B skills/thesis-craft/scripts/project.py --project local/my-thesis import PATH_TO_YOUR_COPY.md
python -B skills/thesis-craft/scripts/project.py --project local/my-thesis status
```

还可以按单元组装上下文、记录候选稿、生成续接说明并导出：

```text
project.py --project PATH context --unit ID --task "审查并润色"
project.py --project PATH record --context CONTEXT_ID --candidate TEXT_FILE --review REVIEW.json
project.py --project PATH resume
project.py --project PATH export --output NEW_DIRECTORY
```
