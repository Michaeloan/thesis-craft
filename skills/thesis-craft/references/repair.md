# 解决问题

本模块把已核实的问题转为正文或文档修改。先修根因，再修表面文字；一个动作只在实际授权范围内实施。

## 选择动作

| 根因 | 首选动作 | 完成标准 |
|---|---|---|
| 表达生硬但论述完整 | 修主语、句序、指代、断句和连接 | 信息关系不变，读者能一次读懂 |
| 对象或指标错配 | 补清对象、指标、分母和条件 | 每个数值与判断有明确归属 |
| 比较分散 | 并置可比项，把依据放回判断附近 | 比较回答明确问题，并形成具体认识 |
| 论述被过度压缩 | 从已有图表、原文和来源补回比较、机制或推论 | 新增内容推进判断，不是说明文字用途 |
| 新对象在后文突然出现 | 将完整结果和选择依据前置，后文只承接和深化 | 读者能从前文理解后文为何选择该对象 |
| 章节重复 | 按定义、结果、解释、应用和结论重新分工 | 同一信息每次出现都有不同任务 |
| 表格承载过多论述 | 将机制、条件和判断写回正文，表格保留比较字段 | 不看表格也能理解本节结论 |
| 证据或计算不足 | 定位来源、图表或计算记录；无法补足则登记缺口 | 不靠措辞把未证实判断写实 |
| 过期或错误审查意见 | 保留当前正确内容，记录不采纳依据 | 不因意见语气或数量重复改坏正文 |
| 页面或 Word 对象问题 | 按word.md或figures.md定点修复并渲染复核 | 文本、对象结构和实际页面均正常 |

内容已经成立时选择“保留”。不要为了显示工作量强行换词。

## 组织长篇论证

新信息通常按以下顺序进入论文：

1. 方法或定义说明对象怎样得到、指标怎样计算；
2. 结果完整呈现主要对象、区域或类型的差异；
3. 讨论选择其中的对象进一步解释、比较或提出应用安排；
4. 结论提炼已经在前文形成的认识。

后文若重点讨论两个地区、类型或案例，先回看结果章是否已经把它们放进全体对象中比较，并给出选择理由。不能直接在应用章节突然写成重点，也不能把讨论中的解释倒填成结果。

## 把人工痕迹改成具体论述

遇到抽象套语时先还原实际关系：

- “形成连续证据链”改为具体说明哪些分析环节相互衔接；
- “作为共同接口”改为说明同一分类在哪些步骤被使用；
- “为后文提供依据”改为直接写前文结果如何影响后续选择；
- “结果具有重要意义”改为可核对的应用对象、差异或条件；
- 连续的“不等于、不能说明、仍需核查”集中到适当边界位置，把正文空间留给结果与判断。

不要做机械禁词替换。若词语是正式术语或确实准确，保留；只有它掩盖具体关系时才改写。

## 移动、合并与删除

移动内容时同时移动其必要引文和限定，并在原位置补足承接。合并段落时保留各自独有的比较、机制和推论。

整块删除前必须：

1. 完整读取待删块；
2. 标出独有事实、公式、引文、作者决定和未完成事项；
3. 确认这些内容已在其他位置保留或明确转移；
4. 搜索后文对标题、图表、编号和结论的引用；
5. 删除后复查目录、引用、图表编号和段落承接。

批量替换仅用于已经确认等价的机械改动。正文语义、跨段结构和章节切分不得使用可跨行匹配的正则直接处理。

## 修改影响检查

每次实质修改向外检查一圈：

- 定义或公式改变：检查所有使用位置、变量说明、图表和附录；
- 结果或数字改变：检查摘要、讨论、结论、图表和单位；
- 段落迁移或删除：检查引文、交叉引用、前后承接和章节任务；
- 术语改变：检查全稿同义词、缩写、图题和表题；
- 图表改变：检查正文解释、图注、目录和复现脚本；
- 作者决定改变：使旧候选和旧问题状态失效，不能继续套用。

只修改一个句子也要检查它是否是后文指代的唯一前项。

## 闭环复核

完成后依次确认：

1. 原问题是否真正消失，而不是换了措辞仍然存在；
2. 原有论点、依据、比较、推论、限定和作者文风是否保留；
3. 新增内容是否有来源，是否改变证据强度；
4. 修改是否造成新的重复、跳跃、突现对象或章节错位；
5. 关联的摘要、结论、图表、引用和页面是否同步；
6. 台账状态是否从“已建议”准确推进到“已修改待复核”或“已闭合”。

默认交付可直接使用的正文。复杂问题可附简短修改说明，说明解决了什么及仍需哪项材料；不要把内部检查过程写进论文正文。
