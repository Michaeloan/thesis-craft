# 长论文工作流

只在整章、全文或多轮持续修改时加载。片段直接使用 polish.md，不要求建立项目。

## 工具分工

智能体负责理解、润色与语义核对；project.py负责导入、上下文、版本和记录。所有命令均先指定论文工作目录：
`python <Skill目录>/scripts/project.py --project <论文工作目录> <命令>`

不要将真实论文复制到Skill源码目录。项目记录写在论文目录内的 .thesis-craft/，不是全局记忆。源文件只读，导出的Markdown不代表已经回写Word。

## 建立项目与概览

1. 运行 init，再 import 原文；读取返回的版本目录 index.json 和导入警告。
2. 对照索引与原文确定章节结构；对疑似标题、复杂表格和修订标记保留待核对状态。
3. 阅读各章的研究问题、定义和结论位置。分批构建 overview、chapter_role、term、fact、issue 记录；同时记录重要地区、类型、指标和案例的首次出现及后续使用，形成“定义/方法—结果—讨论—结论”推进关系。长文不要在同一轮假装已通读所有章节。
4. 每个研究类记录用原文摘句及unit ID定位；外部材料使用来源与页码/段落定位，并如实记录全文或摘要状态。自动归纳设candidate，不伪造作者确认。
5. 通过 record --note 保存。新记录会使之前生成的上下文待重新核对，先建好当前任务必需的记录，再调用context。

概览不是原文替代品。必须保留数字的对象、单位、分母、时期、范围和计算阶段；方法原因不明时登记问题，不编进概要。不得靠多轮概括逐渐丢掉条件。

## 组装本轮上下文

运行 context --unit ID --task "具体任务" --mode polish。读取返回的context_file，不只看命令摘要。

工具将当前单元、命中的项目记录、明确图表/标题引用和相邻段落组包。它不自动理解所有语义关联：
- 对“上述结果”“前述方法”等指代，先回索引定位并补充有来源的记录，再生成上下文。
- 方法定义与结果引用跨章时，登记触发词和原文摘句。
- 核实命中的图号是否是所需图；导入缺少图像内容时不能仅凭图题解释结果。
- 普通润色不自动检索新文献；论述补强需要来源时再读related-work.md。

默认24000字符预算包含可读取Markdown上下文文件，不等同token预算。收到split_required时，用 --start / --end 选择完整块重新生成，或按环境提高预算；不得自己截掉关键定义后继续。若单段加必需证据仍超限，缩小任务或明确需要更大上下文。

needs_evidence表示有过期记录或未定位引用。可以处理不受影响的表达，必须在issues登记缺口，不能声称完成全段事实核验。未确认事实不能因为被纳入上下文而成为事实。

## 润色闭环

先按polish.md诊断本段真正需要修复的问题，决定保留、局部调整或授权重组。结合来源记录本段涉及的专名、比较对象、数值归属、分母、年份和判断限定，再润色与核对。把原文主语错置修好不等于改研究内容；不能在上下文唯一明确时只替词或只提醒而不修复。每段的依据、比较和推论随意思保留，不按模板组织。

将候选正文写成独立UTF-8文件，保留当前块中的标题/表格等内容。填写 review.example.json：
- expression：主语、指代、语序和连接；
- argument：论点、依据、比较和推论是否保留；
- scope：比较指标及对象、数字归属、分母、年份、单位、专名、条件和证据强度；
- paragraph_cohesion：小节内段落承接和重复；
- chapter_cohesion：章任务及前后章关联。
未执行的检查写not_checked，不因字面脚本通过写passed。

record --context ID --candidate 文件 --review 检查JSON 保存候选与实际检查。只有作者明确接受时才使用 --author-confirmed --decision "实际确认内容"；模型自评通过不等于作者接受。

## 多轮、续接与新稿

换会话先 resume，读其状态及所指原文和context_file。继续尚未记录的目标；有候选稿则检查候选，不擅自当作终稿。

作者改原文件后，先重新import。原文或已使用的关联单元变化会使旧记录失效；项目笔记变化也会保守地要求复核。新生成的记录可替代同范围候选。区段重叠时 export会拒绝合并，可用 record --withdraw ID --decision "撤回原因"撤回不采用的候选，历史仍留存。

贴片段更新时保存为本地TXT并以 --kind pasted导入，表示这一段的基线，不表示已同步整篇Word。每个项目当前只有一个活动来源；整篇项目的片段任务优先用块范围，独立粘贴片段使用另一个项目目录，避免误将其作为整篇新版本。

## 两级衔接检查与交付

每节结束核对段落衔接；整章结束核对章节任务、术语、首次出现与后续使用。重点对象若在讨论中突然出现，回到结果章补足全体比较和选择依据，再让讨论深化。局部完成不代表整章检查完成。可以将章节审查作为review模式独立任务，记录具体发现；摘要和结论在正文稳定后复核。

export --output 新目录输出分节候选稿、逐记录对照与状态报告；未处理的原文保留并标记，过期候选排除。含公式、域、修订、图片和表格的区段列入Word核查清单。实际Word回填和页面检查按word.md处理，不将文本交付说成版面验收。
